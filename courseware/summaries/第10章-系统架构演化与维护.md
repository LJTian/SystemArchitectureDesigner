# 第10章：系统架构演化与维护

- **源 PDF**：第10章：系统架构演化与维护-定稿.pdf

## 本章概要

本章说明软件架构演化与维护的目的、定义（组件/连接件/约束）及静态与动态演化分类，并系统列举 18 种可持续演化原则与评估思路。以大型网站架构十阶段演化为实例，覆盖缓存、负载均衡、读写分离、CDN、分布式与业务拆分等实践要点，最后介绍架构维护与可维护性度量（圈复杂度等）。原则名称、演化时期与网站演化阶段是备考重点。

## 知识结构 / 目录提纲

- 软件架构的演化和定义的关系
  - 纠错性与完善性修改；“架构是演化来的”
  - SA = {组件，连接件，约束}
- 软件架构演化方式的分类
  - 按实现与粒度：过程/函数、OO、组件、架构
  - 按研究方法四类；静态演化 vs 动态演化
  - 演化时期：设计时、运行前、有限制运行时、运行时
  - 静态演化五步骤；动态性三级（交互/结构/架构）与演化内容
- 软件架构演化原则（18 种）
  - 成本、进度、风险、主体维持、结构优化、平滑演化…
  - 目标一致、模块独立、影响可控、复杂性可控…
  - 利于重构/重用、遵从设计原则、适应新技术、环境适应、标准依从、质量向好、适应新需求
- 软件架构演化评估方法
  - 演化过程已知/未知；中间版本度量等
- 大型网站系统架构演化实例（十阶段）
  - 单体 → 垂直 → 缓存 → 服务集群/负载均衡 → 读写分离 → 反向代理与 CDN → 分布式文件与库 → NoSQL/搜索 → 业务拆分 → 分布式服务
  - Redis、负载均衡算法、主从复制与分库分表等实践
- 软件架构维护
  - 知识管理、修改管理、版本管理
  - 可维护性六指标：CCN、FFC、CBO、RFC、TCC、LCC

## 核心考点

1. **演化目的**：适应环境变化的纠错性与完善性修改；迭代完善以满足需求。
2. **SA 三元组**：组件、连接件、约束；演化常体现为增删改组件/交互/拓扑。
3. **按粒度分类**：基于过程与函数、面向对象、基于组件、基于架构。
4. **运行前演化**：编译之后、执行之前；不必考虑运行状态，但需支持增删组件。
5. **静态演化五步**：软件理解 → 需求变更分析 → 演化计划 → 系统重构 → 系统测试。
6. **动态性三级**：交互动态性、结构动态性、架构动态性。
7. **18 原则中常考**：演化成本控制（CoE≪CoRD）、环境适应性、质量向好、模块独立/影响可控等。
8. **平滑演化**：演化速率趋于稳定；剧烈变更需警惕。
9. **网站演化主线**：性能与容量驱动下逐步引入缓存、集群、读写分离、CDN、分布式与拆分。
10. **缓存问题**：穿透、击穿、雪崩、预热等（课件结合 Redis 讲解）。
11. **负载均衡**：静态/动态算法；加权轮询、哈希、最少连接等。
12. **读写分离与主从**：binlog 模式；同步方案；分区分表分库。
13. **架构维护三块**：知识管理（架构设计+设计决策）、修改管理（隔离影响）、版本管理。
14. **可维护性六子度量**：CCN、FFC、CBO、RFC、TCC、LCC；高内聚低耦合。
15. **圈复杂度 CCN**：实践上程序规模以 **CCN≤10** 为宜；可用于早期评估测试复杂度。

## 备考提示

1. 先记演化时期定义与“基于组件”等分类填空；再挑 8–10 条原则名称+一句话解释。
2. 大型网站十阶段按“单体→拆分→缓存→集群→数据层→加速→分布式→服务化”串成故事线记忆。
3. 维护部分抓住 CCN≤10、CBO 与耦合、高内聚低耦合即可应对度量题。
4. 动态演化比静态更难：不中断服务下改拓扑/组件是关键差异点。
